# Train / validation / test splits

Generated by `scripts/export_splits.py` from the project's existing processed
feature data (`data/processed/features.parquet`, `data/processed/features_extra.parquet`)
— not retrained, not recomputed from raw source data by this script.

## Source data

- **Disease reports**: EpiClim (Kaur et al., 2025), Zenodo,
  DOI [10.5281/zenodo.14580510](https://doi.org/10.5281/zenodo.14580510),
  CC BY 4.0. Weekly outbreak report records, aggregated here to one row per
  (state, disease, ISO week).
- **Climate**: NASA POWER (`power.larc.nasa.gov`), daily temperature,
  rainfall, and humidity aggregated to the same state x ISO-week grid at a
  single centroid coordinate per state (see `src/fetch_climate.py`).

## Target

`target_reported_h1`: whether the disease was reported in that
(state, disease) the week *after* the feature row's own week — i.e.
"outbreak reported in week t+1", horizon = 1 week. Built by
`src/train_baseline.py`'s `build_horizon_data(1)`, the same function used
for every other horizon-1 result in this project, with its own leakage
assertion (the target week must be exactly 7 days after the feature row's
week).

## Splits

| Split | Date range |
|---|---|
| train | 2009-01-01 to 2017-12-31 |
| validation | 2018-01-01 to 2019-12-31 |
| test | 2021-01-01 to 2022-06-29 |

**2020 is excluded from all three splits.** Every state-disease combination
in this project lost at least 42% of its 2019 reporting rate by 2020 (see
finding F5 in `results/findings.md`), consistent with a shared
administrative disruption (most plausibly COVID-19-era), not a real change
in outbreak frequency. Treating 2020 as a normal year would have trained
and evaluated the models against a reporting regime that doesn't represent
any other year in the data.

Rows are in chronological order within each file — never shuffled, per this
project's data-integrity rules (`CLAUDE.md`).

## Combinations and files

Seven state-disease combinations (see `results/findings.md` F6, F10, F17 for
why these seven and not others): Maharashtra/Dengue, Kerala/Dengue,
Karnataka/Acute Diarrhoeal Disease, Maharashtra/Acute Diarrhoeal Disease,
West Bengal/Acute Diarrhoeal Disease, Gujarat/Acute Diarrhoeal Disease,
Odisha/Acute Diarrhoeal Disease.

Each combination has three files: `<state>_<disease>_train.csv`,
`<state>_<disease>_val.csv`, `<state>_<disease>_test.csv` (lowercase,
underscore-separated), e.g. `maharashtra_dengue_test.csv`.

## Columns

`state`, `disease`, `week_start_date`, `year`, `week`, `reported` (this
week's own indicator), the model's reporting-history/seasonal/climate
feature columns (see `src/build_features.py`'s `FEATURE_COLUMNS`), and
`target_reported_h1`.
